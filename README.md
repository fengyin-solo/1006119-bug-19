# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 进度节点：单一数据口径

进度节点（月底向建设单位报量）历史上出现过“页面临时拼字段、导出另走一条取值路”的问题，
表现为列表 27 条、导出 21 行、册子计划完成日整列丢失、补录节点导不出来。现统一收敛到独立领域台账
`frontend/src/data/progress/`：

- **同一份数据**：列表页、导出 CSV、下载册子、掘进环次交付清单全部读取同一份台账投影
  （`repository.ts` 的 `projectNode/projectAll`），通用 `local-service` 对 `progress` 也委派到台账，
  看板计数同源，不再有第二份条数。
- **缺列逐列标出**：导出固定 9 列，缺失字段在对应格写 `【缺列：计划完成日】` 并在文件末尾附“缺列核对”，整列不删。
- **补录节点**：只在表单里存在的节点与字段迁移时并入台账，补录节点一并导出。
- **偏差天数统一算法**（`deviation.ts`）：已完成=实际完成日−计划完成日，未完成=今天−计划完成日，
  早完为负、逾期为正、缺日期为空（不当 0）；算法升级后已生成的交付清单按新口径重算。
- **计划完成日冻结**：已确认完成的节点计划日禁止改动（建设单位也不行），未完成节点改计划日需监理及以上；
  越权/越级直接驳回并返回所卡步骤。
- **分卷打包/断点续打**：按卷打包，一卷全部投影完成才置完成，失败卷保持未完成、不留半包，可从断卷续打；
  册子必须全部成卷后才能下载；幂等键保证重复提交只生效一次。
- **重复登记**：同节点编号只保留最早登记那条；整批落库失败按事务回滚。
- **存量节点**：迁移时按计划完成日重新入库并重排序号。

领域逻辑不依赖浏览器，回归测试在 `frontend/scripts/progress-domain-test.ts`，运行：

```bash
cd frontend
npm test      # tsc 编译到临时目录后由 Node 执行，断言迁移/导出/续打/冻结/重算等
```
